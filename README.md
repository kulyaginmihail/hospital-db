# Больница

Учебный проект по дисциплине «Базы данных». Кулягин Михаил Евгеньевич, ТюмГУ, Школа компьютерных наук, прикладная информатика, группа БД-13.

PostgreSQL и Flask. Рабочее место администратора: 15 таблиц, просмотр, добавление, изменение и удаление, выбор внешних ключей по названиям, история медкарты, расчет счетов. Данные в примерах вымышлены.

## Требования

- PostgreSQL 17 (проверено на 17.11), доступное расширение `btree_gist` из стандартного contrib.
- Python 3.12 (проверено), pip и браузер.
- Создание базы выполняется владельцем БД. Скрипт схемы запускается только в пустой базе; существующие базы он не удаляет.

## Создание базы

Пример подключения: хост `localhost`, порт `5432`, база `hospital`, пользователь `hospital_app`. Пароль задается пользователем и не хранится в репозитории.

В терминале с PostgreSQL:

```sh
createuser -h localhost -p 5432 -U postgres --pwprompt hospital_app
createdb -h localhost -p 5432 -U postgres -O hospital_app -E UTF8 hospital
psql -h localhost -p 5432 -U hospital_app -d hospital -v ON_ERROR_STOP=1 -f sql/01_schema.sql
psql -h localhost -p 5432 -U hospital_app -d hospital -v ON_ERROR_STOP=1 -f sql/02_demo.sql
```

На macOS вместо `postgres` укажите администратора своего кластера. Если создание расширения запрещено, администратор один раз выполняет `CREATE EXTENSION btree_gist;` в базе `hospital` перед запуском схемы. Скрипт демонстрационных данных запускается один раз. Скрипты не очищают имеющиеся данные.

В Windows команды выполняются в PowerShell после добавления папки PostgreSQL/bin в PATH. Перед psql для кириллицы можно выполнить `chcp 65001`.

## Запуск приложения

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export DATABASE_URL='postgresql://hospital_app:YOUR_PASSWORD@localhost:5432/hospital'
python manage.py create-admin
python app.py
```

В Windows:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:DATABASE_URL = 'postgresql://hospital_app:YOUR_PASSWORD@localhost:5432/hospital'
python manage.py create-admin
python app.py
```

Откройте http://127.0.0.1:8000. Вместо `YOUR_PASSWORD` укажите свой пароль (спецсимволы в URI кодируются). Можно использовать строку libpq: `host=localhost port=5432 dbname=hospital user=hospital_app password=...`. Не добавляйте пароль в git. Параметр `SECRET_KEY` необязателен: без него после перезапуска потребуется войти снова. `PORT` меняет порт HTTP.

Для демонстрации и тестов вместо интерактивного создания администратора:

```sh
python manage.py create-admin --demo
```

Демонстрационный логин `admin`, пароль `HospitalDemo2026!`. Использовать только локально с учебными данными. Для обычного входа создайте собственный пароль.

## Работа

1. Создать пациента, затем его медицинскую карту. Пока карта не создана, прием оформить нельзя.
2. Создать врача и интервал расписания. В форме приема выбрать карту, время и плановую услугу, заполнить жалобы.
3. Перевести прием из «запланирован» в «идет». Добавить оказанную услугу с диагнозом, осмотром, заключением и назначениями; при необходимости добавить исследования.
4. Завершить прием. Завершение без услуги, диагноза и заключения запрещено.
5. Создать счет-черновик и его строки. Указать цену и скидку, перевести счет в «выставлен». При оплате указать флаг и дату одновременно.
6. В таблице медицинских карт нажать «История». В таблице счетов отображается вычисленная сумма.

Цена и скидка в строке счета являются согласованными значениями для конкретного счета, а не ссылкой на текущий тариф. Количество берется из оказанной услуги. Услуга после включения в счет защищена от изменения. Выставленные и отмененные счета со строками не удаляются; неоплаченный выставленный счет можно отменить. Одну услугу разрешено включить только в один счет за всю историю: повторное выставление после отмены в этой упрощенной версии не реализовано. Частичная оплата не предусмотрена.

## Схема и ограничения

`sql/01_schema.sql`: 15 таблиц, 5 доменов, 2 представления, 5 триггерных функций. PK, FK, UNIQUE, CHECK, EXCLUDE защищают ключи, диапазоны и расписание. Везде для ссылок используется ON DELETE RESTRICT. Для многотабличных правил применены триггеры. Изменения из приложения выполняются в транзакциях SERIALIZABLE; при конфликте нужно повторить сохранение.

Медкарта оказанной услуги определяется через прием в представлении `card_service_history`. Это устраняет транзитивную зависимость в таблице услуг и сохраняет просмотр истории по карте. `invoice_total` вычисляет сумму без дублирования поля итога.

Межтабличные проверки предполагают запись через приложение с SERIALIZABLE или ручные транзакции с тем же уровнем изоляции. Прямые произвольные записи с более слабой изоляцией не входят в учебный сценарий.

Ограничения учебной версии: один административный интерфейс; роли врача, пациента, кассира и регистратора хранятся как данные, отдельные кабинеты не реализованы. Нет печати официальной формы, интеграции с ОМС, автоматических резервных копий и производственного медицинского документооборота. Допускается ввод исторических приемов. При изменении тарифа длительности существующее расписание автоматически не перестраивается. У пациента может быть 0 или 1 карта, у врача одна должность. Дополнительные диагнозы и назначения являются текстом заключения, не структурированными списками для аналитики.

## Проверка

В отдельной учебной базе выполните схему, демонстрационные данные и создайте администратора `--demo`. Затем:

```sh
python tests/test_project.py
```

Пять тестов: CRUD для всех 15 таблиц, 17 отказов SQL, откат ошибочного HTTP-запроса и CSRF, история/сумма счета, проверка входа и скрытия хешей. Тест CRUD удаляет только свои временные записи. Основные демонстрационные записи не удаляются.

`sql/03_queries.sql` содержит примеры JOIN, LEFT JOIN, GROUP BY и выборки истории карты.

## Структура

- `app.py`: маршруты, транзакции, формы, вход.
- `metadata.py`: русские подписи, разделы и статусы.
- `templates/`, `static/`: HTML и оформление.
- `manage.py`: создание администратора, пароль хранится в виде scrypt-хеша.
- `sql/`: схема, демонстрационные данные, запросы.
- `tests/`: проверки на реальном PostgreSQL.

Приложение слушает только 127.0.0.1; встроенный сервер Flask используется для локальной защиты работы.
